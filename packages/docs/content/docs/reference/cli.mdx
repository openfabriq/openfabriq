`[folder]` is a repository root or its `openfabriq/` folder, the current folder by default. `openfabriq --help`, or `openfabriq` alone, lists the commands; `openfabriq --version` prints the installed version.

![openfabriq with no command: its mark, then every command and what it does.](/screenshots/cli/usage.png)

## Write and apply a factory

| Command | What it does |
| --- | --- |
| `openfabriq init [folder]` | Opens Claude Code with the `setup` skill: it reads the repository, asks a few questions, writes or changes `openfabriq/`, validates it and explains the plan |
| `openfabriq init --example <name>` | Copies a [template](/templates/), with the repository and your login filled in |
| `openfabriq validate [folder]` | Checks the files |
| `openfabriq doctor [folder]` | Says what this machine lacks to run the factory: Claude Code, `gh`, git, the sandbox's tools on Linux, and every program `setup`, the commands and the MCP servers start (their first word). When the engine works as a GitHub App, checks that the app is installed on the factory's repository. Lists the factory's secrets that are not set (see `secret set`). For a skill that installs a program, says the program is installed, or that it is missing; prints the rest of a skill's `compatibility` (what it needs) for you to check. Names the sites the factory calls outside its [`network`](/factory/harness/#network), and the sites its last runs were refused. For an [imported skill](/factory/skills/#import-a-public-skill), says whether it was changed since it was imported, and asks GitHub whether its repository has a newer version. Installs and runs nothing |
| `openfabriq skill add <owner/repo> [skill] [--agent name \| --area name]` | Copies a public skill from GitHub into `openfabriq/skills/`, an area's or an agent's skills, pinned to its commit in `openfabriq/imported-skills.json`. Run it again to update the skill. See [Import a public skill](/factory/skills/#import-a-public-skill) |
| `openfabriq skill remove <folder>` | Removes an imported skill and its entry, like `openfabriq skill remove skills/code-review` |
| `openfabriq plan [folder]` | Shows what `apply` would change, security changes first |
| `openfabriq apply [folder] [--yes] [--project owner/repo]` | Creates the labels on GitHub, then this machine runs the factory. Shows the plan and asks "Apply this plan to owner/repo?"; `--yes` skips the question, for a script. `--project` refuses a `factory.yaml` that names another repository |

## Run the factory

| Command | What it does |
| --- | --- |
| `openfabriq start [folder] [--interval s] [--port n]` | Watches and runs every applied factory, every 60 seconds by default (`--interval` or `OPENFABRIQ_INTERVAL`, 10 or more). Serves the studio on `127.0.0.1:4310` (`--port` for another), at the address it prints with `?token=`. One engine per engine folder (`~/.openfabriq`, or `OPENFABRIQ_HOME`): a second `start` on the same folder refuses. In a repository whose factory changed, it first shows the plan and applies it once you confirm. At most 4 runs at once, all projects together (`OPENFABRIQ_MAX_RUNS`, 1 to 32); the others wait. `Ctrl-C` stops it |
| `openfabriq status` | Lists the runs in progress, waiting and recent |
| `openfabriq mcp` | Serves the factories, their runs, numbers and board, read only, to an MCP client such as Claude Code or Claude Desktop, over stdio. See [MCP server](/mcp/overview/) |
| `openfabriq update` | Installs the latest openfabriq with npm, or `brew upgrade` when Homebrew installed it. From the sources or in Docker, says how to update instead. `start` prints a line when a new version is out |
| `openfabriq run <automation> [--issue n \| --pr n] [--project owner/repo]` | Asks `start` to run an automation now. Only one with a GitHub event or a `schedule` in `when`, not one that starts only from Slack, Linear, Sentry or a webhook. `--issue` or `--pr` when it starts on one, neither when it runs on the whole repository. `openfabriq run wiki` generates or updates the [wiki](/factory/wiki/) |

## Connect services and secrets

| Command | What it does |
| --- | --- |
| `openfabriq connect github [--org name] [--workflows] [--url u]` | Creates your team's GitHub App and saves its key on this machine; the engine then works as the app, with a token per repository, instead of `gh`'s login. Shows no secret: `connect github env` gives a server's variables. `--org`: an organization owns the app. `--workflows`: also asks for *Workflows: write*, so the app can push to `.github/workflows/`. `--url`, the studio's https address: the app also handles [sign-in with GitHub](/deployment/docker/#sign-in-with-github), and the command saves its client too. See [A GitHub App instead of a token](/deployment/docker/#the-github-app) |
| `openfabriq connect github env` | Prints the saved app's variables for a server's `.env`: `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY` on one line, and the client of sign-in with GitHub when there is one. Redirect it, so the secrets stay off the screen: `openfabriq connect github env >> .env` |
| `openfabriq connect github token <owner/repo>` | Prints the app's token for one repository, valid for an hour, for a script: `GH_TOKEN=$(openfabriq connect github token acme/web-app) gh repo clone acme/web-app` |
| `openfabriq connect relay [--url u]` | Deploys the [relay](/deployment/relay/) on your Cloudflare account, or connects to one running at `u`. Every service below goes through it |
| `openfabriq connect slack` | Points a Slack app at the relay; the bot token stays on this machine |
| `openfabriq connect linear` | Installs openfabriq as an app in Linear, through the relay: labels and delegation |
| `openfabriq connect sentry` | Tests a Sentry auth token and gives it to the relay, which looks for new issues |
| `openfabriq connect webhook <name> [--remove]` | Lets the relay receive a webhook of `factory.yaml`, or stops it |
| `openfabriq deploy coolify` | Runs the engine on your [Coolify](/deployment/coolify/), through its API: asks for Coolify's address and API token and a Claude credential, masked, uses the GitHub App of `connect github`, creates the application, sets its variables, gives the studio a domain if you want, with sign-in with GitHub, a password, or both, deploys, and reports what the engine's checks say. Never prints a secret |
| `openfabriq secret set <NAME> [--project owner/repo]` | Asks for the value of a secret the factory declares, and stores it on this machine only |

## Environment

The data folder (`OPENFABRIQ_HOME`), service tokens, an Anthropic API key, the studio's password and address, and the factory's secret values: see [Environment variables](/reference/environment/).

## The studio without the engine

To read past runs without polling, serve the studio from the sources:

```bash
pnpm --filter @openfabriq/studio serve                 # prints http://127.0.0.1:4310/?token=…
PORT=4399 pnpm --filter @openfabriq/studio serve --fake-chat
```
